# Data model and transformation mapping

This document describes the current DuckDB/dbt build. IDs are unique numeric identifiers generated by persistent DuckDB sequences; the two registry databases under `results/lakehouse-direct/` must be retained. Product IDs persist by normalized SKU. Source-row and quote IDs persist only for the same source hash and record position; a changed file creates new source-row identities. They are not guaranteed stable business identifiers for corrections, reordering, or incremental loading.

| Output | Grain and ID | Source and transformation |
| --- | --- | --- |
| `dim_product` | One normalized SKU; `product_id` | Trim and uppercase SKU values from accepted sales and inventory, international sales and price-sheet rows. |
| `stg_sales_lines` | One accepted Amazon line; `sales_line_id` | Validate order, SKU, date, quantity, amount precision and B2B flag. Join product ID. |
| `stg_inventory` | One unambiguous SKU observation; `inventory_snapshot_id` | Reject missing or duplicate normalized SKUs and invalid stock. Snapshot date is unknown. |
| `stg_international_sales` | One accepted international line; `international_sale_id` | Validate date and numeric fields; currency is unknown. Customer name is excluded. |
| `stg_price_sheet` | One price-sheet source row; `price_sheet_row_id` | Preserve the two price sheets and join SKU when present. No effective date or realized cost is assumed. |
| `fact_price_quote` | One metric from one price-sheet row; `price_quote_id`; FK `price_sheet_row_id` | Unpivot 11 or 12 columns per source row. Preserve raw value and parse status; currency unknown. |
| `stg_expense_rows` | One original row; `expense_row_id` | Retain receipt and expense text without asserting transaction-level allocation. |
| `stg_warehouse_rows` | One original row; `warehouse_row_id` | Retain comparison-sheet text without assigning actual delivery cost. |
| `mart_source_quality` | One source; source code | Reconcile accepted and rejected rows; retained source rows are not necessarily verified transactions. |
| `mart_fulfillment_category` | One fulfillment/category pair | Count lines and cancellations; calculate descriptive line-level rate. |
| `mart_inventory_category` | One category | Count accepted SKU observations and zero-stock observations in the undated snapshot. |

The raw source files are copied into Parquet with source row numbers and SHA-256 provenance. Raw files may include names and addresses; they stay local and are Git-ignored. Quality validation does not prove source accuracy. Original sales and inventory remain independent; joining stock to dated sales would not establish historical stock. dbt tests cover selected IDs, relationships, source reconciliation, and quote coverage.
